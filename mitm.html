Man in the middle attack
Closer than you might actually think...

You initiate a file donwload.

You begin by downloading a file, such as software or an update, from a legitimate and trusted website. Your request is sent over the internet to retrieve the authentic file from the developer's server.

The attacker intercepts the download.

Without your knowledge, an attacker intercepts the connection between you and the server. This can happen on the server side, where the attacker compromises the server or reroutes your traffic using a DNS attack. Alternatively, if you are on an unsecured network, such as public Wi-Fi, the attacker can intercept the communication directly.

Malicious code is injected.

After intercepting the file, the attacker modifies it by injecting malicious code. The tampered file is then forwarded to you, appearing unchanged. You download and install the compromised software, unknowingly running harmful code on your system.

This is where the power of the hashbrowns come into play.
And don't worry - it might seem daunting - but they are already baked in.

1. Software creation

The software developer writes the source code which are turned into binary 0's and 1's object code.

A cryptographic hash (e.g., SHA-256) is applied to the software to create a unique hash value.

2. Hash publication and download

The developer or distributor publishes the hash value of the software alongside the download link on their website.

Hash values allow comparison of the user-generated hash with the one provided by the software distributor.

3. Software downloaded and user generates hash for verification.

The user downloads the software from the websites.

The user compares the hash they generated locally with the hash value provided by the developer.

4. Avalanche effect

A matching hash confirms that the file is genuine and hasn’t been tampered with. A mismatch signals corruption or malicious modification.

The slightest change in the input results in a different hash value, making tampering easy to spot.
